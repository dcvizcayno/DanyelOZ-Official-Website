# T-001 Research: where sync metadata and licensing settings live

Run: r-20261121-1250-sync-readiness. Role: researcher. Decision informed: data layout, app placement and
widget read path for sync fields (C-1..C-5).

## Answer (up front)

1. Put the per-song public sync fields as **new columns in the public `tracks` tab**, added by header name
   through the existing `namedTab_` path, but only from **new `sy*` functions in a new `Sync.gs`** (not by
   extending `TRACK_COLUMNS`, which would break an existing unit test and touch every Tracks call).
2. Put shared licensing settings in a **new public one-row tab `sync_settings`** in the Song Database
   (one header per setting), edited from a settings card on the Tracks screen; widgets read it by gviz
   `&sheet=sync_settings` with a header guard against the "missing tab returns Sheet1" trap.
3. Per-song "Sync" tab goes into the existing editor tab strip in `TracksApp.html`; the readiness view and
   settings form are new cards in `TracksViews.html`. Confidence: high (all from primary code).

### Q4. Where shared settings should live

| Option | For | Against | Reversibility |
|---|---|---|---|
| **A. Public tab `sync_settings` (one row, one header per setting)** | Same path as every other admin-edited public tab (`namedTab_` + `lock_` + `safeText_`); widgets already read tabs by gviz; edits show within minutes; no token; add a setting = add a header | Public (fine: all are public facts); gviz quirks (keep all `@` text); needs the Sheet1 guard | Easy: delete tab |
| B. `data/sync-settings.json` in danyeloz-embeds | Same-origin fetch, no Sheet1 trap, versioned | App needs a GitHub write token and commit flow; ~10 min Pages delay; second source of truth beside the sheet | Easy |
| C. Script Properties | Private, simple to write | Widgets cannot read them without a new public web endpoint; out | n/a |

Recommendation: **A**, one-row wide layout read by header name. Suggested headers (all text):
`rights_holder, rights_line, one_stop, pro_name, contact_email, contact_url, turnaround, process_note,
updated`. Blank `pro_name` means widgets print no PRO name (C-5). A key/value two-column layout was
considered; it needs a custom upsert and breaks the "read by header name" convention. (medium-high: design
inference on top of high-confidence facts)

## Recommended design (for the planner)

Data (public `tracks`, added by header name on first sync use, text `@` unless noted):
`bpm` (whole 40-220, stored as text), `key` (fixed list), `moods` (comma separated, fixed list),
`sync_genre`, `writers`, `producers`, `vocal` (fixed list, e.g. Male/Female/Duet/Instrumental-only),
flags `has_instrumental, has_clean, has_stems, has_cut30, has_cut60, one_sheet` written always as
`'TRUE'` or `''` text (the `bonus` pattern, Tracks.gs:332 and RT_TEXT_COLUMNS :18) so the column is one type;
`explicit` reused as is. Widgets parse flags with the `bool_` regex.

Server: new `apps-script/Sync.gs` with `SY_TRACK_COLUMNS`, `SY_SETTINGS_TAB = 'sync_settings'`,
`SY_SETTING_COLUMNS`, `SY_MOODS`, `SY_KEYS`, `SY_VOCALS`, `SY_MAX_FEATURED = 10`; helpers `syTracksTab_()`
= `trPublicTab_(TRACKS_TAB, TRACK_COLUMNS.concat(SY_TRACK_COLUMNS), TRACK_TEXT_COLUMNS.concat(text sync cols))`;
callables `getSyncAdmin()` (per-ISRC sync fields, readiness counts, settings, lists, and private
`track_notes` bpm/key as a "copy from studio notes" hint), `saveTrackSync(isrc, d)` (validate, count
featured across the tab under `lock_()`, `trPutRow_`), `saveSyncSettings(d)` (one row, `safeText_`, https
check on `contact_url`). `getTracksAdmin`/`getTrackDetail` stay unchanged (keeps test_tracks.js:53 green).

Client: TracksApp.html: add `['sync','Sync']` to the tab list (:204) and a `syncPane()` that lazy-loads
`getSyncAdmin` once into `TK.sync`; add a readiness card render and a settings form render. TracksViews.html:
two new cards ("Sync readiness" with complete/missing counts and a missing-fields list; "Licensing settings"
marked public) plus `.sy-*` styles. No Form.html change needed.

Tests: new `tests/unit/test_sync.js` (load Code, Shorts, Singles, Tracks, Sync; assert columns appended
after `abc` without moving data, validation errors, featured cap, settings round trip); add stubs to
`tests/ui/mock.js`; new `tests/ui/sy.js` at 1400 and 390.

Widgets: `sync.html` and `sync-one-sheet.html` fetch `&sheet=tracks`, `&sheet=sync_settings`, `&gid=0`;
guard heads; copy the albums.html parser, fonts and reds; fallback text when settings or tracks missing.

## Counter-evidence and limits

- Did not confirm live sheet contents (no sheet reads in this run); a hand-added column named `bpm` or
  `key` could already exist in `tracks`, in which case `namedTab_` would reuse it (by design, but its data
  type is unknown).
- The Sheet1 fallback of gviz for an unknown `sheet=` is inferred from the guards and the skill text, not
  re-tested here.
- `mailto:` for the contact email is not `https://`; the widget rule allows only https links
  (CLAUDE.md:155). Needs a decision (allow `mailto:` for the settings email only, or show the address as
  text plus an https form link).
