## Coverage against the definition of done

- Constants: SY_TRACK_COLUMNS (the 14 D-1 names, in order), SY_SETTINGS_TAB = 'sync_settings', SY_SETTING_COLUMNS (D-5 plus `updated`), SY_MOODS (20, from T-002 R-1), SY_GENRES (12, from R-2), SY_VOCALS = Solo vocal, Duet, Instrumental only, Mixed (**D-9**, not plan.md's "Male vocal"), SY_KEYS (24), SY_MAX_FEATURED = 10, SY_DEFAULTS. Extra constants: SY_FLAG_COLUMNS, SY_REQUIRED, SY_MAX_MOODS, SY_NAMES_MAX, SY_EMAIL_RE.
- `getSyncAdmin()` does zero writes, enforced by a counter on every mock write: setValue, setValues, clearContent, setNumberFormat, setFontWeight, insertSheet, create, setProperty. It reads by header through `getSheetByName`, never through `namedTab_` or `vaultTab_`. Studio hints come from the vault only if VAULT_SHEET_ID is set and the `track_notes` tab exists. It never creates a vault.
- `saveTrackSync` runs under `lock_()`. All validation, the ISRC lookup and the featured count happen before `trPublicTab_(TRACKS_TAB, TRACK_COLUMNS.concat(SY_TRACK_COLUMNS), SY_TRACK_COLUMNS)`, so a rejected save writes nothing (tested for every rejection). Writes go through `trPutRow_` with string values: safeText_ is applied and flags are 'TRUE' or ''. Only the sync columns get `@` formatting.
- Rejections tested:
  - BPM 39, 221, 120.5, "fast" and 1200.
  - Key not in the list, including a wrong-case key.
  - Genre and second genre not in the list.
  - Vocal "Male vocal".
  - Unknown mood, and a 4th mood (given as an array and as text).
  - Writers or producers over 200 characters.
  - 11th featured song.
  - Unknown ISRC and malformed ISRC.
- Allowed values tested: BPM 40, BPM 220, re-saving an already featured song, and featuring again after unfeaturing.
- `saveSyncSettings` runs under `lock_()` and creates the tab on the first save. It checks the email pattern (rejects blank, malformed and `?subject=`). `contact_url` must be blank or https (`http:` and `javascript:` rejected). Values go through writeNamed_/safeText_ and `updated` is set by manilaNow_(). The round trip and the one-row rewrite are tested.
- Formula escaping is tested in tracks (`=HYPERLINK`, `+1`) and in settings (`=IMPORTXML`).

## Return shape (for T-006)

`getSyncAdmin()` returns:
- `tracks[]`: `{isrc, track_title, first_release, explicit:boolean, language, sync_* ..., complete:boolean}`. `sync_moods` is an array, the six flags are booleans, and `sync_bpm` is a string.
- `readiness{complete, total, missing[{isrc, title, fields[]}]}`. `fields` holds column names from SY_REQUIRED.
- `settings{...}`: text values, `one_stop` 'TRUE' or ''.
- `settings_saved:boolean`.
- `lists{moods, genres, vocals, keys, max_moods, max_featured}`.
- `hints{ISRC: {bpm, key}}`.

`saveTrackSync(isrc, d)` takes the full sync form. Missing keys are saved as blank. Moods can be an array or comma-separated text.

## Reopen (G1 security conditions SR-05, SR-06, SR-07, SR-09, D-10)

Same write scope; only apps-script/Sync.gs and tests/unit/test_sync.js changed.

### What changed in Sync.gs
- **SR-06 `syText_(v, max, label)`**: replaces U+0000-U+001F and U+007F with spaces, collapses whitespace, trims, and refuses text over the limit. The formula guard `safeText_` is then applied exactly once, by `trPutRow_` / `writeNamed_`. Calling it inside syText_ as well would double the apostrophe. Every text write goes through syText_. `trPublicTab_` sets the `@` format on the sync and settings columns before any data cell is written. Header cells are written by `namedTab_` before formatting, as in the existing Tracks.gs pattern. Flags are only the string 'TRUE' or ''.
- **SR-05 `syPublicText_`**: applied to sync_writers, sync_producers, rights_holder, rights_line, pro_name, turnaround and process_note. It refuses `https?://`, `www.`, `drive.google`, `docs.google`, any email address (in settings, the submitted contact_email itself is allowed), 9+ consecutive digits, and the words IPI/CAE. Each refusal gives a reason. Writes are built only from SY_TRACK_COLUMNS / SY_SETTING_COLUMNS, so unknown payload keys are ignored. Nothing stores licensing requests. Studio hints return only bpm/key.
- **SR-07**: BPM is a whole number 40-220 (`120abc` refused); key, genre, genre_2 and vocal come from the lists; genre_2 must differ from genre; moods: at most 3, all from the list; flags must be boolean or TRUE/FALSE/empty (`syFlagIn_`; "yes" is refused). Writers and producers are capped at 200. Settings limits are in `SY_SETTING_MAX` (rights_holder 120, rights_line 400, pro_name 80, turnaround 40, process_note 600, contact_email 120, contact_url 500). Over-limit text is refused, not cut. The ISRC must already exist, so no row is created. The featured count and the write run in one `lock_()` section. All validation happens before any write.
- **SR-09**: `updated` is always `manilaNow_()`; a client value is ignored (tested with `updated: '1999-01-01'`).
- **D-10 `syContactUrl_`**: blank, or https with the host exactly one of www.danyeloz.info, docs.google.com (path must start `/forms/`), forms.gle or www.cognitoforms.com. The host is stored lower-case.

### Deviations (reopen)
1. Apps Script V8 has no `URL` class, so D-10's "parse with a URL parser" is done with a strict hand parser: authority = everything up to the first `/ ? #`, which must equal an allowlisted host exactly. That rejects `user@`, `:port` and look-alikes; backslashes and whitespace are refused anywhere. The widgets (T-005) can use `new URL`.
2. Moods may still be blank on save (0-3), like BPM. "1+ mood" is enforced as part of readiness (D-4), not as a save error, so a half-filled song can be saved. Security's SR-07 text says "1-3 moods"; the Supervisor or security may ask for a hard minimum.
3. The SR-05 email exception applies only in settings free text, and only for the submitted contact_email. Track fields refuse every email.
4. `git status` shows apps-script/TracksApp.html and TracksViews.html modified. Those are not mine (outside this scope, presumably T-006 running in parallel).
