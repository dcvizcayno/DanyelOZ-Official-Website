## Defects

### D-1: the popup opened from the embed can open a second tab (chain): S2, blocks release
- Criterion: C-2 ("No link between the two pages ever opens a second new tab in a chain").
- Minimal repro: (1) Frame sync.html in the sandbox above. (2) Click Get the one-sheet, then Print or save as PDF. Page P1 opens (the one-sheet, top-level). (3) In P1, click the catalogue link. P1 navigates to sync.html in the same tab, which is correct. (4) In P1, click Get the one-sheet, then Print or save as PDF. Page P2 opens, and its opener is P1.
- Expected: no second new page from P1. Actual: 2 new pages in total, and P2's opener is P1. Seen at 1400 and 390.
- Evidence: probe output "FAIL 1400 sync.html framed CHAIN popup then catalogue then print opens no second page :: {pagesOpened:2, secondOpenedFromFirst:true}" (the same at 390).
- Suspected scope: sync.html showSheet() always adds the print link with target _blank (via link()), even when sync.html is the top-level page that the embed's popup became. Repeating steps 3 and 4 keeps adding tabs, which is the loop the run was meant to remove. The fix is the executor's call.

### D-2: repeated Print or save as PDF clicks from the embed open one tab each: S3, follow-up
- Criterion: C-2 ("opens the printable one-sheet in at most one new tab"); the brief's "never more than one new page in total".
- Repro: in the framed catalogue, open the one-sheet view, click Print, click Back, open the one-sheet again, click Print. That gives one more new page per click.
- Expected per the brief: the total stays at 1. Actual: one per click. Rated S3 because each click is a deliberate print action. The supervisor may raise this to S2 if "at most one new tab" means in total rather than per click.

## Not verified, and why
- Real Google Sites embed: not reachable offline, so I used an equivalent sandbox attribute set. Sites may add allow-popups-to-escape-sandbox. That would not change D-1, because the chain happens in the popup.
- The copy success path ("Email copied.") never runs, because the frame has no clipboard-write permission. Only the fallback was exercised, which is the path Sites users get.
- Print page count was checked on the standalone one-sheet at 1400 only (print layout does not depend on viewport width). The in-catalogue sheet view's print was not page-counted.
- Browsers: Chromium only.
- I did not modify any executor test, so independence holds for every check.
