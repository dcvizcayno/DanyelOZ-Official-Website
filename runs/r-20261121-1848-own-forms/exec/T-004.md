## Public API for T-006 / T-007 (window.OZForms)

- Constants: `CONFIG_URL`, `PRIVACY_URL` (`https://www.danyeloz.info/about/privacy`), `EMAIL`, `MIN_FILL_MS` (3000),
  `HONEYPOT` ('website'), `FIELDS` (deep-frozen; each field `{key,label,type:'text'|'email'|'long'|'choice',required,max,help?,choices?,control?:'radio'|'select'}`), `EMAIL_RE`, `ACTION_RE`.
- `validEmail(v)`, `validAction(url)`, `validConfig(raw, key)` -> `{action, fields}` | null, `loadConfig()` -> Promise(JSON|null), cached per page.
- `validate(key, values)` -> `{ok, errors:{fieldKey: message}}`; `encode(key, cfg, values)` -> URLSearchParams.
- `submit(action, params)` -> Promise resolving `true` when sent; rejects on refused action (fetch not called), error or 15 s timeout.
- `render(root, key, opts)` -> `{node, destroy}`. opts: `prefill` {fieldKey: value} (text only, honeypot not prefillable,
  choices only if in list), `turnaround` (sync success text, default `3 business days`), `onUnavailable` (node is removed,
  then called, instead of the email fallback).
- DOM hooks for tests: root `.ozf.ozf-<key>`; contact draws `h2.ozf-h` "Contact & Collaborations" + `p.ozf-intro` (contact.html
  must not add its own); `p.ozf-loading`; `form.ozf-form` (novalidate); fields `.ozf-f`, inputs carry `name=<fieldKey>`
  (contact topic: radios `input[type=radio]` named by id, value = choice); errors `p.ozf-err`; honeypot `.ozf-hp input[name=website]`;
  button `.ozf-send`; status `p.ozf-status`; success `p.ozf-ok` (role=status, focused); fallback `.ozf-fallback` with
  `.ozf-mail` and `button.ozf-copy`; privacy `p.ozf-privacy a`.
- Harness: `mock.route(page, tabs, {forms})` and `mock.sandboxPage(browser, width, file, {forms, tabs})` ->
  `{ctx, page, frame, errors, navs, popups, log}`; `log.posts` = `[{url, body, headers}]`; `forms`: undefined -> `{}`,
  `'fixture'`, a status number (404), or an object. `mock.fetchStub(tabs, log, {forms})` for vm tests (`log.posts[i].init`).

## Deviations (declared)

1. PRIVACY_URL is `/about/privacy` (charter D-2, FR-12), not plan.md's `/privacy`.
2. Privacy note text follows FR-12: `I use what you send only to reply to you and handle your request.` (plan.md had the
   shorter sentence). T-005 policy wording should match.
3. Action id bounded `{20,120}` and the URL is also parsed (href round-trip, https, host exactly docs.google.com, no
   user/password/port/query/hash), per FR-04a; total length capped at 200.
4. "One send per render": after a successful (or honeypot) send nothing more is sent; after a failed send the button is
   re-enabled so the visitor can retry, values kept.
5. `mock.route` now adds `Access-Control-Allow-Origin: *` to fulfilled responses (catalogue.js already did this itself)
   and attaches `log.posts`; the URL log is unchanged.
6. test_formscore.js includes a short Playwright smoke of `render` (errors, fill time, honeypot, valid POST without
   cookie/referer, fallback, onUnavailable, prefill) in addition to the pure-function tests; T-006/T-007 still own the
   full widget tests.
7. The config fetch also sets `referrerPolicy: 'no-referrer'`; FIELDS carries an extra `control` property.
8. FS_FORMS cross-check loads the whole FormsSetup.gs in an empty vm context (its top level references FS_PROP_*), and
   compares key, label, type, required, choices, max, help.
